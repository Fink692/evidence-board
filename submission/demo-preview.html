00:00 — The decision

Evidence Board gives a research decision room to be questioned. This fictional university is considering longer library hours during exams. The current argument looks plausible, but do its sources actually justify keeping the building open all night?

00:16 — Read the sources

Seventy-two percent of voluntary survey respondents wanted later hours. The question did not specify how late. Meanwhile, only eight percent of trial entries occurred after midnight. That is a share of entries, not occupancy or unmet demand. The original wording stays visible beside the claim.

00:36 — The integration surface

Ten structured WebMCP tools expose this shared board to a compatible browser agent. Native registration and invocation have been tested in Chromium. The setup panel reports actual availability. Tools can inspect evidence and prepare proposals, but none can approve a change.

00:55 — The labelled rehearsal

For this walkthrough, I’m using Run demo rehearsal: a fixed six-call script through those same handlers, with no model or API key. It proposes three changes and leaves every one for human review. Nothing has entered the accepted record.

01:13 — Human review

The first proposal connects overlooked counterevidence. The second makes the survey–usage tension explicit. The third adds a question about exam weeks versus ordinary weeks. Each has its own rationale and proposed result. I’ll keep the link and conflict, make the explanation more careful, and leave the new question out.

01:38 — Approval

Only when I click Apply selected does the accepted board change. The unselected question is rejected. Invalid references or an outdated revision are checked before a proposal or approval is committed, so a failed operation cannot leave half a change behind.

01:55 — The accepted record

The decision brief is a deterministic, cited snapshot of the accepted board. The accepted link and conflict are included; the rejected research question is absent. I can copy it or export Markdown. This is the evidence record we reviewed, not a fresh AI answer.

02:15 — Trace and Undo

Activity identifies the rehearsal and records tool inputs and results. Undo restores the previous accepted content. A structured list and JSON backup keep the same research usable even when native browser-agent support is unavailable.
